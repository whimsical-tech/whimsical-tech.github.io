### まず、全体像を把握しよう

どこへ行くかを知るには、先に自分がどこにいるかを知る必要がある。

チュートリアルでは、[このリポジトリ](https://github.com/whimsical-tech/i18n-nextjs-tutorial)を出発点とする。

もちろん、ゼロから独自のプロジェクトを始めたい場合でも、すでに独自のアプリケーションをお持ちの場合でも、問題なく手順に沿って進めることができる。
TypeScriptを使用して型安全性を確保する。

このアプリケーションに英語オプションを追加する。

アプリでさらに言語を追加したい場合や、他の言語を追加したい場合も、手順はほぼ同様ですので、その点についても説明する。

### リポジトリのブランチについて
P.S.: 推奨されているリポジトリを使用していない場合は、このセクションを読み飛ばしてください。

- _initial_: これは翻訳前のプロジェクトが置かれているブランチだ。チュートリアルをゼロから始めたい場合は、こちらから始めてください。
- _master_: ここではリポジトリが100%翻訳されている。i18n化された完成品のプロジェクト例を見たい場合は、このブランチを使用してください。
- _test_: このブランチは記事の内容を厳密に追従し、最後に至るまで翻訳や明示されていない変更は一切行わない。

完全な翻訳は難易度が高いため、初級者の方はこれを目標として挑戦してください。もし行き詰まったら、解答を確認しながら進めても問題ない。


### 基本設定

ご想像の通り、まず最初に行うべきことは、いくつかのパッケージをインストールすることだ。

`npm install i18next react-i18next`

それでは、いくつかの基本的なファイルを作成しよう。
まず、プロジェクトの基本設定が必要だ。

このファイルを「i18n-config.ts」と名付ける。これをルートフォルダに配置する。

```ts
export const i18n = {
  defaultLocale: "ja",
  locales: ["en", "ja"],
} as const;

export type Locale = (typeof i18n)["locales"][number];

export const hasLocale = (locale: Locale) => {
  return i18n.locales.includes(locale);
}
```

このファイルでは、ウェブサイトのデフォルト言語を定義する。使用する言語の配列を記述し、アプリ内に存在する言語と照合して一致するかどうかを確認する簡単なチェックを行う。

次に、翻訳データを読み込む。Node.jsのビルド時にimport()がバンドリングの問題を引き起こす可能性があるため、翻訳データは別のファイルとして用意する必要がある。


```ts
import type { Locale } from "./i18n-config";

const locales = {
  en: () => import("../locales/en.json").then((module) => module.default),
  ja: () => import("../locales/ja.json").then((module) => module.default),
};

export const getTranslation = async (locale: Locale) =>
  locales[locale]?.() ?? locales.ja();

```

読み込まれたパスに対応するフォルダとファイルも必ず作成してください。他の言語を使用する場合は、それに応じて追加してください。コンパイルエラーを防ぐため、すべての翻訳ファイルに空のオブジェクト {} を追加してください。後でそこに翻訳された文字列をすべて追加するが、まずは設定を続けましょう。

app フォルダの直下に [lang] という名前のフォルダを作成してください。角括弧は重要で、lang が動的パラメータであることを示す。[lang] の中にはすべてのページを配置する。

![This is how the directory currently looks like](../../directory.png "This is how the directory currently looks like")

現在、アプリは URL に手動でパラメータを追加しないとアクセスできない。これを修正するため、app フォルダと同じ階層に proxy.ts ファイルを作成する。ただし、Next.jsのv16以前を使用している場合は、代わりにミドルウェアファイルが必要だ。


```ts
import { NextRequest, NextResponse } from "next/server";
import { i18n, Locale } from "./i18n-config";

const { defaultLocale, locales } = i18n;

function getLocale(request: NextRequest) {
  const acceptLanguage = request.headers.get("accept-language");
  if (!acceptLanguage) return defaultLocale;

  const preferredLocales = acceptLanguage.split(",").map((lang) => {
    const code = lang.split(";")[0].replace(/\s+/g, "");
    return code.substring(0, 2);
  });

  const matched = preferredLocales.find((lang) =>
    locales.includes(lang as Locale),
  );
  return matched ?? defaultLocale;
}

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl;
  const pathnameHasLocale = locales.some(
    (locale) => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`,
  );

  if (pathnameHasLocale) return;

  const locale = getLocale(request);
  request.nextUrl.pathname = `/${locale}${pathname}`;

  const response = NextResponse.redirect(request.nextUrl);
  return response;
}

export const config = {  matcher: [
    "/((?!_next|public|favicon\\.ico|.*\\.(?:png|jpg|jpeg|gif|webp|svg|ico)$).*)",
  ],
};
```

URL に言語パラメータが含まれていなくても、自動的にリダイレクトが行われる。ただし、コンテンツ自体はまだ変更していないため、すべての言語で同じ文字列が表示されたままになる。

重要な点は、関数を非同期（async）にし、プロパティにパラメータを追加し、awaited パラメータから lang を取得することだ。

ブラウザで表示を確認し、URL の言語を変更すると ```<html lang="">``` が切り替わることを確認してください。有効なのは設定ファイルに記載された言語のみだ。

近づいてきた！
次に、ユーザーに言語変更の組み込み機能を提供したいので、ロケールスイッチャーを作成する。複数の言語を追加する場合でも役立つよう、オプション付きのドロップダウンは拡張性のある選択だ。components フォルダに追加した。


```tsx
"use client";

import { useRouter, usePathname } from "next/navigation";
import { useTransition } from "react";
import { Locale } from "@/i18n-config";
import { useTranslation } from "react-i18next";

const locales: Record<Locale, { name: string; flag: string }> = {
  en: { name: "English", flag: "🇬🇧" },
  ja: { name: "日本語", flag: "🇯🇵" },
};

export default function LanguageSwitcher() {
  const router = useRouter();
  const pathname = usePathname();
  const { i18n } = useTranslation();
  const [isPending, startTransition] = useTransition();

  const currentLocale = i18n.language;

  const handleChange = (event: React.ChangeEvent<HTMLSelectElement>) => {
    const newLocale = event.target.value as Locale;

    startTransition(async () => {
      await i18n.changeLanguage(newLocale);

      const newPath = pathname.replace(`/${currentLocale}`, `/${newLocale}`);
      router.push(newPath);
    });
  };

  return (
    <div
      style={{ display: "inline-flex", alignItems: "center", gap: "0.5rem" }}
    >
      <select
        id="language-select"
        value={currentLocale}
        onChange={handleChange}
        disabled={isPending}
      >
        {Object.entries(locales).map(([code, { name, flag }]) => (
          <option key={code} value={code}>
            {flag} {name}
          </option>
        ))}
      </select>
      <span
        style={{
          display: "inline-block",
          width: "16px",
          height: "16px",
          visibility: isPending ? "visible" : "hidden",
        }}
        aria-hidden={!isPending}
      >
        {isPending && <div className="spinner" />}
      </span>
    </div>
  );
}
```

## ハードコードされた文字列から、翻訳ファイルから取得したテキストへ

Next.js で翻訳を使用する際、クライアント側またはサーバー側で読み込むことができる。サーバー側の方が一般的に好ましい。なぜなら瞬時に完了するためだ。まずはこの方法について話そう。

SiteHeader.tsx を起点とするのはページ読み込み時に明確に表示されるためだ。

14 行目には、このハードコードされた文字列が表示される。「日本各地の売買・賃貸をワンストップでサポートします」,英語ではおおよそ「One-stop support for buying, selling, and renting throughout Japan」と訳される。

プロジェクト内のすべての翻訳済み文字列は、JSON 値として表現される。この例では、slogan が適切な名前だろう。したがって、en.json には以下のように記述する：

```
{slogan: "One-stop support for buying, selling, and renting throughout Japan"}
```

ja.json には以下のように記述する：

```
{slogan: "日本各地の売買・賃貸をワンストップでサポートします"}
```

tsx では、ハードコードされた文字列を {t["slogan"]} に置き換える。

t という名前は任意で構わない。「translate」という完全な単語を使いたいかもしれない。

さて、翻訳を追加するコンポーネントに変更を加えよう。

サーバーコンポーネントにする必要がある。

ロケールを パラメータ から抽出する必要があるため、まず親ページでそれを取得する。

```tsx
  return (
    <div className={styles.page}>
      <SiteHeader active="home" lang={lang} t={t}  />

```
その後、翻訳が使用されるコンポーネントにそれを渡す。今回の場合、SiteHeader.tsx だ。
```tsx
export async function SiteHeader({
  active,
  lang,
  t,
}: {
  active: NavKey;
  lang: Locale;
  t: Awaited<ReturnType<typeof getTranslation>>;

```
大半のケースでは、locale と getTranslation の両方を渡す必要はなく、後者のみで十分だ。 しかし、SiteHeader.tsx にはナビゲーションリンクが含まれているため、ローカライズされた URL を構築するために lang を追加する必要がある。 現在の locale を尊重する必要があるリンクを含むコンポーネントには、このパターンを忘れないでください。


```tsx
  <Link href={`/${lang}/`} className={styles.brand}>
    ...
  </Link>
  <nav className={styles.nav} aria-label="主要ナビゲーション">
    <Link
      href={`/${lang}/`} >
      ...
    </Link>
    <Link
      href={`/${lang}/about`} 
      ...
```
これでローカライズされた文字列が表示され、移動中に正しいロケールが維持されるはずだ。 極端に単純化したバージョンはこうなる：すべてのサーバーコンポーネントでこれを行えば完了だ。

### クライアントサイド

対話型のクライアントコンポーネントや、サーバーレンダリングが不可能な場合は、異なるパターンを使用する必要がある。

React Context に既に慣れているなら、ツリー全体でプロパティを無限に渡さずにアプリ全体で情報を簡単に提供する方法だと知っているはずだ。 同様に、layout.tsx で Provider を使用して、アプリ全体に言語を渡す。

```tsx
"use client";

import { ReactNode, useEffect } from "react";
import { I18nextProvider, initReactI18next } from "react-i18next";
import { Locale } from "@/i18n-config";
import i18next from "i18next";
import en from "../../locales/en.json";
import ja from "../../locales/ja.json";

export function I18nProvider({
  children,
  lang,
}: {
  children: ReactNode;
  lang: Locale;
}) {
  useEffect(() => {
    if (!i18next.isInitialized || i18next.language !== lang) {
      i18next.changeLanguage(lang);
    }
  }, [lang]);

  return <I18nextProvider i18n={i18next}>{children}</I18nextProvider>;
}

```
